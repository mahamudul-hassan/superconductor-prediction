# Code accompanying: "Quantifying Subgroup-Valid Uncertainty in Superconducting
# Critical Temperature Prediction: A Locally-Normalized Mondrian Conformal
# Prediction Framework"

## Data

Download `train.csv` and `unique_m.csv` from the UCI Machine Learning Repository:
https://archive.ics.uci.edu/dataset/464/superconductivty+data

Place both files where the scripts expect them (edit the hard-coded path
`/mnt/user-data/uploads/train.csv` / `unique_m.csv` at the top of each script,
or symlink a local `data/` folder to that path). Create an `artifacts/`
directory alongside the scripts before running anything — every script reads
and writes its intermediate results there.

## Environment

Python 3.10+, with: `pandas`, `numpy`, `scikit-learn` (1.8), `optuna` (5.0),
`matplotlib`. Node.js with the `docx` npm package for script 39. All model
fitting was done single-threaded (`n_jobs=1`); expect the Optuna scripts to
take several minutes each on modest hardware.

## Which scripts to run: the final pipeline

The scripts are numbered in the order they were actually run. **Only the
scripts listed in this table are needed to reproduce the manuscript's
numbers, tables, and figures.** Everything else (scripts 01-27) is earlier,
exploratory work that the manuscript's results supersede — see "Exploratory
/ superseded scripts" below for why they're still included.

| Script | Produces |
|---|---|
| `00_create_partition.py` | Formula-grouped train / held-out-pool partition (`grouped_splits.npz`), and a further formula-grouped train2/validation split of the training set alone (`inner_split.npz`) used only for hyperparameter tuning |
| `28_benchmark_6_models.py` | Trains and evaluates all six candidate algorithms (random forest, extra trees, histogram gradient boosting, k-nearest neighbors, ridge regression, SVR) on the held-out pool — Table 2 / Fig. 3 |
| `29_optuna_tune_extratrees.py` | Bayesian (TPE) hyperparameter search for extra trees on the leak-safe inner validation split — Fig. 4. Resumable via the local `optuna_study.db` SQLite file; run it more than once to add trials |
| `30_train_final_tuned_extratrees.py` | Refits extra trees with the best-found hyperparameters (200 trees) on the full training set; reports the train/held-out overfitting-diagnostic numbers in Section 3.3 |
| `31_extratrees_tree_std.py` | Per-compound ensemble spread (the $\sigma(x)$ normalizer) from the tuned extra-trees model on the held-out pool |
| (reuses `13_LEAKFREE_cqr_train.py` + `18_optuna_tune_cqr.py` + `19_LEAKFREE_train_final_tuned_cqr.py`) | The CQR quantile-regression baseline does not depend on which point-predictor won the benchmark, so these three scripts from the earlier pass are reused as-is |
| `32_FINAL_method_comparison_extratrees.py` | **The** headline result: vanilla / Mondrian / normalized / normalized+Mondrian / CQR compared over 300 formula-group-aware repeated splits at the 80% target (Tables 4 and 5; Figs. 7-8) |
| `33_FINAL_reliability_extratrees.py` | Same repeated-split protocol swept over 70/80/90% confidence for vanilla CP and the proposed method (Table 3, Fig. 6) |
| `34`-`38_make_fig*.py` | Figures 1-2 (EDA, model-independent, can also be generated by `22_make_fig1_fig2_eda.py`), 3 (benchmark), 4 (hyperparameter importance), 5 (parity), 6 (reliability), 7-8 (subgroup coverage/width) |
| `39_make_highlights_docx.js` | Generates the standalone `highlights.docx` (run with `node`) |

Note the confidence-level choice: a 95% sweep was attempted and is **not**
reported. With only six Mondrian taxonomy cells, some containing fewer than
100 calibration compounds, the empirical quantile needed for 95%
group-conditional calibration becomes numerically unstable (a handful of
extreme calibration residuals can dominate a small cell's threshold,
occasionally overflowing on exponentiation). We judged it more honest to
report 70/80/90% only than to publish a number driven by that instability.
If you re-run at 95%, expect to need a wider or merged taxonomy, or a
minimum-cell-size safeguard, to get sensible numbers.

## Key methodological notes for anyone re-running this

- All conformal-prediction thresholds use the finite-sample-corrected quantile
  level `ceil((n+1)*(1-alpha))/n`, not the naive `(1-alpha)` quantile.
- The Mondrian taxonomy is `number_of_elements`, bucketed into six groups
  (`<=2, 3, 4, 5, 6, >=7`) to keep per-group calibration-set sizes adequate.
- The locally-normalized nonconformity score divides the log-space residual by
  `(tree_std + eps)`. **`eps = 0.1`** in the final (extra-trees) pipeline —
  note this differs from the value used in the earlier, superseded
  random-forest pass (`eps = 0.02`), which produced numerically unstable
  normalized scores for a small fraction of compounds with near-zero
  ensemble spread. Use 0.1 if you extend this work.
- Repeated-split evaluation (scripts 32, 33) holds the trained base learner(s)
  fixed and repeatedly re-partitions only the held-out pool (calibration +
  test) into fresh calibration/test subsets, reassigning whole formula groups
  each time. This measures calibration-induced variance, not full
  retrain-per-split variance — stated explicitly as a limitation in the paper.
- Optuna studies are stored in a local SQLite file (`optuna_study.db`) so that
  `n_trials` can be extended across multiple runs without losing prior trials;
  the random-forest and extra-trees studies are separate named studies in the
  same file (`rf_tuning`, `et_tuning`).

## Exploratory / superseded scripts (01-27)

These reflect the actual order of investigation and are kept for
transparency, but **do not** feed into the manuscript's reported numbers:

- **01-10**: a first pass using a plain random 80/10/10 split (no formula
  grouping) with a random-forest base learner.
- **11-21**: the same analysis redone with the formula-grouped partition
  (created inline at the time; script `00` now reproduces this step
  standalone) and a random-forest base learner, including its own Optuna
  tuning pass (`15_optuna_tune_rf.py`) and full method comparison
  (`20_LEAKFREE_FINAL_method_comparison.py`). This is a complete, internally
  consistent alternative pipeline — it just isn't the one the manuscript
  reports, because the six-model benchmark (script 28) subsequently showed
  extra trees outperforms random forest.
- **22-27**: figure-generation scripts for the random-forest pipeline above,
  superseded by `34`-`38`.

If you want the random-forest version of every result instead of the
extra-trees version actually reported, scripts 11-27 are a complete,
self-contained pipeline for that.
